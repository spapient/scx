# scx 性能基准表（跨机参考）

> 本表只做量级参考与回归对照，不是跨机器性能承诺。数据来自本机 release 构建，
> 每行标注机器型号、日期、编译 profile 与测量方法；不同行**口径不同，不可直接
> 跨行比较**（例如结构语料与默认语料内容不同，max-tokens 路径受证据地板交互影响）。
> 日期：2026-10-25（P4 新增路径首次记录）。

## 环境与方法（2026-10-25）

- 机器：Apple M5 Pro（Mac17,9），macOS 27.0.1，arm64
- 编译：`cargo build --release --locked`（profile.release opt-level=3 / lto / strip）
- 方法：预热 1 次后采样 N 次取中位；N 默认 9（压缩）/ 21（召回），可用
  `SCX_BENCH_REPEAT` 覆盖；与同一会话中历史基线交错测量避免漂移。
- 命令：`cargo run --release --locked --example bench`（压缩四路径）/
  `-- memory`（记忆库）

## 压缩路径（50k 行）

| 路径 | 语料 | 中位 | 样本（µs） | kept | 备注 |
|---|---:|---|---:|---:|---|
| 默认 | 心跳+每百行 ERROR（2,338,389 字符） | 14,757 µs | 13190–22113 | 2498 | 本轮单轮采样负载偏高；历史快照 11.7–12.0 ms（三轮交错中位）为基准值 |
| `--structure 1` 关 | 结构富语料（import/stack/fence+噪声，1,438,623 字符） | 7,888 µs | 7750–8539 | 3002 | 与开启同语料对比用 |
| `--structure 1` 开 | 同上 | 8,813 µs | 8654–12581 | 3002 | 相对关闭 +12% 增量开销；kept 不变（结构并入不改变证据地板） |
| `--max-tokens 2000` | 默认语料 | 12,029 µs | 11655–12181 | 1499 | `mode=overflow:evidence`（证据地板 > 2000，全部证据保留并如实报告） |
| `--policy-file` 字段覆盖 | 默认语料 | 15,345 µs（压缩） | 14958–15610 | 1499 | TOML 解析 <1 µs（4 行，per-invocation）；稳态压缩延迟与字段覆盖等价 |

口径说明：
- `--policy-file` 的 TOML 解析是 **CLI 一次性开销**（读文件 + TOML 子集解析），
  实测 <1 µs，不进入每次压缩的热路径；完整 CLI 映射在 `args::parse_policy_file`，
  本表为字段级近似（ratio/context/max_tokens/structure 代表字段）。
  2026-10-27 修正：此前本节把「首次冷压缩」误标为 TOML 解析（13–15 ms），
  基准计时已改为只覆盖解析本身。
- `--max-tokens` 路径报告的是**加了上限检查的压缩延迟**；overflow 分支保留
  全部证据行（证据地板最高优先），不做静默裁剪。
- 结构语料行更短（1.44M vs 2.34M 字符），绝对值不与默认语料横向比较；两行
  structure 之间同语料可直接比较增量。
- 2026-10-27：`structures()` 的大括号计数由「每行两次 `matches().count()`」改为单趟
  字节扫描；同轮 `structure:on − off` 增量中位 1635 → 1461 µs（5 轮交错，波动约 ±300 µs），
  输出逐字节一致。

## 真实转储：`--guard-region` 收益（2026-10-27）

语料：本仓库 Claude Code 会话转储中工具输出最大的 3 份（`tools/extract_dumps.py
--extract 3`，17.6k–26.4k 行 / 1.1–1.4 MB）。命令：`tools/bench_real.py
--binary target/release/scx`（query 默认 `compress dedup evidence`，ratio 0.35）。

`--guard-region 1` 只在 `--risk-gate 1` 且风险 HIGH 时生效：HIGH 风险下风险守卫会把
**全文所有**错误/标记行都保留，区域门控则只保留证据邻域内的，远处无关错误行照常裁剪。

| 转储 | ctx | gate | gr=0 压减 / kept | gr=1 压减 / kept | 压减提升 |
|---|---:|---:|---:|---:|---:|
| 79879b8d | 0 | 1 | 66.9% / 2961 | 86.9% / 851 | +20.0 pt |
| 79879b8d | 1 | 1 | 61.4% / 3892 | 81.5% / 1782 | +20.1 pt |
| 90a4c2af | 0 | 1 | 75.8% / 2493 | 87.5% / 915 | +11.7 pt |
| 90a4c2af | 1 | 1 | 72.6% / 3454 | 84.3% / 1876 | +11.7 pt |
| aa48d465 | 0 | 1 | 68.5% / 1942 | 81.8% / 724 | +13.3 pt |
| aa48d465 | 1 | 1 | 65.0% / 2674 | 78.3% / 1456 | +13.3 pt |

- `gate=0` 时守卫不运行，`gr=0/1` 输出逐字节一致（表中未列，已实测相同）——门控不是
  全局开关，只在风险守卫触发时改变行为。
- 三份转储在 `ctx=0/1 × gate=1` 下 kept 均降到原来的 29%–46%，压减率提升 11.7–20.1 个百分点。
- 口径：`guarded` 字段是 0/1 标志位（是否触发守卫），不是被守卫行数；行数变化见 kept 列。

## 去重折叠优化循环（6 轮，2026-10-27）

对象：`compress::dedup`（归一化后第 3 次起的重复行折叠）。方法：每轮先改后测，
三份真实转储 × 60 次运行的 user CPU（交替测量），只有当输出 `--json` 逐字节
不变且计时不劣于基线才保留。

| 轮次 | 改动 | 结果 | 处置 |
|---|---|---|---|
| 1 | 基线（`ccd0bc6`） | 79879b8d 0.73s / 90a4c2af 0.96s / aa48d465 0.72s（各 60 次） | — |
| 2 | trim 后 <6 字节短行直接跳过归一化 | 无可测收益；剖析显示新增 `trim` 占 ~2.5% | 回退 |
| 3 | 键改 64 位哈希 + 字节 arena（免每键 String 分配） | **慢 3–4%**（0.72→0.75 / 0.95→0.98 / 0.71→0.74）：二级桶与切片比较得不偿失 | 回退 |
| 4 | 与上一行原文相同则复用上一次归一化结果 | 略优且方向一致（90a4c2af 0.96→0.95、aa48d465 0.72→0.71，两轮复现） | **保留** |
| 5 | 差分性质测试：确定性 LCG 生成 300 组含连续重复/数字/十六进制/空白/短行的语料，与朴素参考实现逐位比对 dedup 结果 | 通过 | 保留 |
| 6 | 收尾：清理临时剖析入口、全量门禁、记录本表 | clippy 0 warning / 340 tests 全过 | — |

结论：去重的剩余成本几乎全部是「每行归一化 + 键哈希」的固有开销，两次结构性
重构（短行快速路径、哈希分桶）均无收益或被实测否决；保留的唯一优化是连续重复
行的归一化复用（约 1–2%）。Fnv-1a 实现收敛到 `hash::fnv1a`，记忆库身份键与去重
共用一份算法。

## 每行 token 估算表复用（2026-10-27）

压缩路径此前对同一批行最多调用 3 次 `terms::estimate`（masks 累计、填充预算、
保留行记账）。改为 masks 一次算好每行估算写入表，填充与记账直接复用；小输入/
针尖档不建表，调用方回退现算。输出逐字节一致（6 份语料核对）。

| 转储 | 改前 user CPU（60 次） | 改后 | 变化 |
|---|---:|---:|---:|
| 79879b8d | 0.72–0.73s | 0.69–0.70s | 约 −4% |
| 90a4c2af | 0.92–0.93s | 0.91–0.92s | 约 −1.5% |
| aa48d465 | 0.69–0.70s | 0.68s | 约 −2% |
