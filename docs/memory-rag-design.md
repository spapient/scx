## 0. 摘要

在 scx（本地查询感知证据筛选压缩器，v0.4.1，Rust 零依赖）之上，新增**记忆知识库（RAG）**：每次压缩任务的产物（证据块 + 元数据 + 用户反馈）自动沉淀为知识条目，检索时以本地召回优先（L1），模型综合兜底（L2），外部搜索仅作最后手段（L3）。目标：

1. 把"每次的经验"变成可检索资产，同类问题二次遇到直接本地召回解决，减少模型 / 外部搜索调用。
2. 全部功能保持 scx 的核心承诺：**零依赖、离线、确定性、只删不改、输出 = 输入子集**。
3. 检索质量目标：在 scx 语料（日志 / 错误堆栈 / diff / 命令输出）上，自研统计向量召回 ≥ 通用 embedding 模型，用可重放评估证明（而非声称）。

**v0.2 三个新目标**：
- 判别信息结构化：稀有 token（错误码 / 文件行 / 路径 / ID）不再埋在 BM25 里，而是抽成可精确匹配的字段（O1），这是统计方法系统性赢过语义模型的根基。
- "上次怎么解决的"最短路径：query→case 记忆图 + 会话缓存（O2/O3），同类问题二次提问零检索直答。
- 经验不只是数据，还有状态：solved/open/regressed 三态 + 反馈双环（O4/O5），让 L1 置信和排序随库真实分布自适应。

## 1. 核心不变量与约束（红线，任何设计不得违反）

| #  | 不变量       | 含义                                | 设计影响                                   |
| -- | --------- | --------------------------------- | -------------------------------------- |
| N1 | 只删不改      | 保留行原文逐字，工具只删不写                    | 召回内容绝不直接注入压缩正文                         |
| N2 | 输出 = 输入子集 | 压缩结果是当前输入行的子集                     | 记忆只做**旁路参考（mem: 段）或评分先验（--mem-boost）** |
| N3 | 纯函数引擎     | `scx::compress` 零文件 / 环境 / 进程 I/O | 记忆逻辑独立为 `scx::memory` 模块，compress 永不触碰 |
| N4 | 零依赖       | Rust 零依赖、离线构建、跨平台自举               | 检索 / 存储用自研实现；任何第三方依赖只作为 feature 开关，默认关 |
| N5 | 确定性       | 同输入同输出，无随机源                       | 索引 / 召回无随机源；ANN 若引入须固定种子并明确标注 "近似"     |
| N6 | 差分门       | 既有压缩输出逐字节不变                  | 任何记忆特性不得改变既有压缩输出；门禁作为验收门               |
| N7 | 库可自愈      | 索引段损坏不得导致整库不可用（O7）               | 段尾 crc + 魔数，坏段丢弃，rebuild 兜底               |

## 2. 总体架构

五层 + 两个环（反馈环 + 记忆图环）：

```
输入层 → 摄取层 → 存储层 → 索引层 → 检索层 → 注入/消费层
                    ↑__________________________|
                         反馈环（--rate / 领域IDF回流）
                    ↑__________________________|
                         记忆图环（query→case 复用）
```

### 2.1 输入层

日志 / 命令输出 / diff / 错误堆栈 / 大文件（触发条件与现状一致：>200 行输出、>500 行文件）。

### 2.2 摄取层

`scx::compress`（不变）→ 输出证据块（种子 ±context 最小可读邻域，只删不改）→ 证据块作为入库文档。

**摄取即过滤**：入库的不是原始日志，而是已被筛出的高密度证据。

**v0.2 增强 — 结构化字段抽取（O1）**：摄取证据块时复用 classify.rs，抽四类判别字段写入 case.json：

| 字段族        | 来源（复用现有分类器）                  | 示例                     |
| ----------- | ---------------------------- | ---------------------- |
| error_code  | is_err / 错误词面邻近 token      | conn_id=9f2a、errno=28   |
| file_loc    | is_frame / is_lineref        | Pool.java:214、rs/lib.rs:88 |
| symbol      | is_frame 行内标识符 + 行引用      | acquire、connect_timeout |
| num_fp      | 数字/十六进制归一化指纹（norm_into）   | "#:#" 折叠后的稳定指纹         |

检索时字段精确匹配权重显著高于词面匹配（见 3.2）。

### 2.3 存储层（资产，可迁移）

```
~/.scx-memory/                     # 默认库位置，--mem-dir 可覆盖；每项目一库（默认隔离）
├── meta.toml                      # schema 版本、embedding 引擎版本、领域 IDF 快照、库统计
├── cases/
│   └── <YYYY-MM-DD>_<hash8>/      # 一个 case 一个目录（hash 来自 query+证据块指纹）
│       ├── case.json              # 文档（证据块正文）+ 元数据（见 4.1 schema）
│       ├── vec.bin                # 稀疏向量（词ID→权重，紧凑二进制，量化 u16）
│       └── tags.json              # 标签、来源、过期策略、反馈记录
└── index/                         # 索引（缓存，可重建）
    ├── postings.bin               # 倒排索引（词面 + 字段联合，O1）
    ├── qmap.bin                   # query→case 记忆图（O2）
    └── ann.bin                    # ANN 索引（预留，USearch 形态，feature 开关）
```

原则：**cases/ 是资产，index/ 是可丢弃缓存**——换后端或换 embedding 引擎，一条 `rebuild` 命令全库重建。

### 2.4 索引层

* **当前**：自研稀疏倒排（词 → case ID 列表，delta+varint 变长编码 + skip list）。v0.2 加入**字段联合倒排**（O1）：每字段族一张子倒排，term 精确匹配时在分数上叠加字段加权项。
* **query 记忆图（O2）**：`qmap.bin` 为 query 归一化指纹 → 历史命中 top-k case 的有向映射，append-only + 定期合并。
* **预留**：ANN（HNSW，借鉴 USearch 设计：M=16、ef\_construction=200、ef\_search 参数化、紧凑内存布局、mmap 加载），仅当（a）接入稠密 embedding 且（b）库 ≥10 万条时启用。
* 规模决策：<1 万条线性扫描 / 1 万 - 10 万倒排 IVF />10 万 ANN。
* **崩溃一致性（O7）**：每个索引段尾部写 crc32 + 魔数；加载时校验，坏段整体丢弃并记录，`rebuild` 自动重建。断电/中断不会让整库不可用。

### 2.5 检索层（召回管线，见 3 节）

BM25 加权 → **字段精确加权（O1）** → **query 记忆图直达（O2）** → **会话缓存（O3）** → PRF 查询扩展 → 时间衰减 → MMR 多样性 → 反馈词级调权 → **场景桶过滤（O6）** → 实体边一跳扩展（可选）。

### 2.6 注入 / 消费层

* `mem:` 段（旁路输出，默认）：召回 top-K 附在压缩结果旁，独立标记，Agent 参考。
* `--mem-boost`（评分先验）：召回案例的高 IDF 经验词并入 query 词表，影响种子候选评分 ——**结果仍是当前输入子集**。
* 分级策略：L1 本地直接答 / L2 模型综合 / L3 外部搜索（见 5 节）。

## 3. 召回管线（质量层，逐级增强）

### 3.1 特征：BM25 稀疏向量（而非朴素 TF-IDF）

* 特征空间：词表（英文 token + CJK 滑窗，复用 `build_terms` 逻辑）。
* 权重：BM25（k1=1.2，b=0.75），长度归一化解决日志行长度差异巨大的得分通胀。
* 存储：只存非零项（词 ID + u16 量化权重），紧凑二进制。

### 3.2 字段精确匹配加权（O1，v0.2 核心）

在 BM25 词面分之上，若 query 中解析出错误码 / 文件行 / 符号 / 数字指纹，与 case 的 `fields` 精确匹配：

```
score = bm25_score
      + Σ_fields  match(field) * FIELD_WEIGHT
FIELD_WEIGHT: error_code=3.0, file_loc=2.5, symbol=2.0, num_fp=2.0
```

理由：日志语料的判别信息在稀有 token（错误码、ID、路径、行号），统计方法在这里**结构性优于**语义泛化——embedding 会把 `conn_id=9f2a` 与 `conn_id=ab01` 视为近义，而我们精确识别同 ID 复发。这是"比 embedding 还好"最可证明的一层，直接进评估（第 10 节）。

### 3.3 query 记忆图直达（O2，v0.2 核心）

* 每次 `--recall` 成功后，记录 (query 归一化指纹 → top-k case IDs)。
* 二次遇到**相同指纹**的 query：直接返回历史 top-k（合并最新反馈权重），跳过整个 BM25 管线。
* 变体（同指纹 + 小编辑距离 ≤ 2）：走记忆图命中后仅做轻量重排（新词面仍参与 MMR）。
* 与语义缓存的区别：语义缓存只缓存"本查询结果"，记忆图缓存"查询与案例的关联"，反馈更新时记忆图可平滑反映。

### 3.4 会话缓存（O3，v0.2 新增）

* 进程内存 LRU，键 = 会话 query 指纹；窗口默认 30 分钟（`session_cache_minutes`，0 = 关闭）。
* 同一会话连续追问同一问题（"上次那个连接池爆掉"）直接命中，零磁盘检索。
* 仅影响 recall 路径，不影响压缩路径；会话结束即释放。

### 3.5 领域 IDF 自学习

* IDF 权重来自**本知识库自己的文档频率**，而非通用语料假设。
* meta.toml 存 DF 快照，写入时增量更新受影响词，检索不扫全库。
* 效果：库内高频判别词（conn\_id、pool、errno）权重自动放大；库越用越准。

### 3.6 PRF 伪相关反馈（查询扩展）

粗召回 top-K 后，取其中高 IDF 高频词反向并入查询词，再召回一轮。统计方法独有优势（embedding 做查询扩展很难），且与 `--mem-boost` 天然合流。

### 3.7 时间衰减

相似度 × 衰减因子 `1/(1+age_days/τ)`，τ 默认 90 天。近的优先，旧的不硬淘汰。**动态 τ（可选增强）**：solved 且反馈为正的 case τ 拉长（经验值 180 天），regressed 的 case τ 缩短（30 天）——不引入新机制，仅用现有状态机参数化。

### 3.8 MMR 多样性（去冗余）

贪心选取：下一候选 = argmax (与 query 相似 − λ・max (与已选集合相似))，λ 默认 0.5。避免 top-K 全是同一故障变体。

### 3.9 反馈词级调权（轻量 LTR，Rocchio 简化版）

`--rate good|bad <case-id>` 后：

* good 词 +Δ 权重（默认 +0.1 / 次），bad 词 −Δ（默认 −0.15 / 次），权重有上下限（±0.5）。
* 只调词权重，不重新训练；可解释、可回滚、毫秒生效。
* **v0.2 双环（O4）**：词级调权之外，case 级质量分 `quality = good/(good+bad)` 进入排序先验（见 4.1）与 L1 置信校准（见 5 节）。

### 3.10 场景桶过滤（O6，v0.2 新增）

* case 自动归类到场景桶（基于 error_code 家族 + 命中词聚类，简单哈希分桶：db / network / build / disk / runtime / other）。
* 检索时先按 query 词面判定候选桶（≥1 个），仅在候选桶内扫倒排——**零成本精度提升 + 检索降耗**。
* 桶由 tags.json 冗余存储，可手动修正（修正走 feedback 记录，可审计）。

### 3.11 实体边一跳扩展（迷你图检索，可选）

复用现有 EXTS 扩展名表与行引用检测，抽取实体（错误码 / 函数名 / 路径 / 文件：行）建 `case↔实体` 边。召回命中实体时沿边扩一跳取兄弟 case—— 解决 "词面桥断、实体桥连" 的跨案例关联。

### 3.12 两级缓存

* LRU 精确缓存：query 完全相同 → 直接复用上次结果。
* 语义缓存：query 归一化后与缓存内 query 相似度 > τ（默认 0.85）→ 复用。
* 命中即跳过检索，这是 "减少模型调用" 最直接的一层。

## 4. 存储 Schema（字段级）

### 4.1 case.json（v0.2 增列以 ✚ 标注）

```
{
  "schema": 2,
  "id": "2026-10-22_a1b2c3d4",
  "created_at": "2026-10-22T10:30:00+08:00",
  "updated_at": "2026-10-22T10:30:00+08:00",
  "expire_at": null,
  "query": "数据库连接超时 conn_id",
  "terms": ["数据库连接", "超时", "conn_id"],
  "text": "<证据块正文>",
  "source": ["/path/build.log"],
  "tags": ["db", "timeout"],
  "bucket": "db",                                  ✚ O6 场景桶
  "fields": {                                       ✚ O1 结构化字段
    "error_code": ["conn_id=9f2a", "errno=28"],
    "file_loc": ["Pool.java:214", "rs/lib.rs:88"],
    "symbol": ["acquire", "connect_timeout"],
    "num_fp": ["#:#"]
  },
  "status": "solved",                               ✚ O4 状态机
  "stats": {"kept": 12, "total": 450, "cut_pct": 94.2, "risk": "HIGH"},
```

## 5. 分级检索（减少模型依赖的核心机制）

```
查询 → 归一化 → ①会话缓存命中？──是──► 返回会话内案例（零磁盘）
                        │否
                        ▼
            ②query 记忆图命中？──是──► 返回历史 top-k（轻量重排）
                        │否
                        ▼
                   召回 top-K（3.x 管线：字段加权 → BM25 → 桶过滤 → MMR）
                        │
                        ▼
        置信度判定：L1 阈值自适应（O5）
        ┌──────────┬──────────┴──────────┐
     L1 高置信      L2 中置信               L3 零/低命中
     本地直接作答   模型综合（召回作上下文）    fail-open：
     输出要点行摘要  召回已注入，模型只做精炼    明确告知需外部信息
     不问模型                             或发起外搜
                        │
                        ▼
                  --rate 反馈 → 双环回流（词级 + case 级）
```

### 5.1 L1 置信自适应（O5，v0.2 核心）

* 固定 τ₁=0.55 的问题：库规模、同类密度不同，固定阈值要么误答（低质量相似判 L1），要么过度降级（好召回被踢到 L2 白花钱）。
* 替代：**动态基线 + margin 判据**
  * 基线：库内 top1 相似度的中位数分布自适应（`l1_base = P50(top1_sim 历史)`，随 --rate 反馈滑动更新，存 meta）。
  * 判据：`sim_top1 ≥ l1_base` **且** `(sim_top1 − sim_top2) ≥ l1_margin_min(0.15)` 且 扩展命中率 ≥ τ₂(0.30)。
  * margin 判据天然防"两个候选都差不离"的误答——差得足够开才敢本地直答。
* **L1 输出要点行摘要**：不吐整块证据，而是 fields.error_code + fields.file_loc + 证据块内错误行（复用风险守卫行语义），全长 < 300 字符，默认展开全文用 `--recall-detail`。这延续 scx "省 token" 的使命。

### 5.2 分级消耗

* L1 覆盖率预期：同类问题二次查询绝大多数停在此层（"上次怎么解决的"）。
* L2 只把召回 top-k 当上下文，模型做综合/精炼，不再全文重读输入。
* 置信度参数全部入 meta.toml，可调。

## 6. 更新机制（及时更新的五个动作）

| 动作   | 机制                                                                | 触发            |
| ---- | ----------------------------------------------------------------- | ------------- |
| 增量写入 | 压缩完成自动 append（默认关，`--store 1` 开启）；写后台化（write-behind），结果先回显，入库后台执行 | 压缩结束时         |
| 去重   | 归一化指纹（复用 norm\_into）→ 已存在则更新 updated\_at 与反馈计数，不新增                | 写入时           |
| 过期清理 | expire\_at + 时间阈值双条件；`gc` 命令执行 tombstone 标记 + 惰性物理删除              | 手动 / 定期       |
| 反馈标注 | `--rate good\|bad <case-id>` → 词级调权 + case 状态机 + 质量分（O4）                  | Agent / 用户使用后 |
| 索引自愈 | 段尾 crc 校验失败 → 丢弃坏段 + 记录 + rebuild 重建（O7）                     | 加载 / rebuild   |

索引维护：追加式写入（append-only）+ tombstone + 周期 `rebuild`（合并碎片、重算 DF 快照、合并 qmap）。删除不立刻重组，零碎片写放大。

## 7. CLI 草案（v0.2 增列以 ✚ 标注）

```
scx --query "..." file.log                       # 现有行为，逐字节不变
scx --query "..." --store 1 file.log             # 压缩 + 入库
scx --query "..." --recall 5 file.log            # 压缩 + 旁路召回 top5（mem: 段）
scx --query "..." --mem-boost 1 file.log         # 经验词扩展评分（结果仍是输入子集）
scx --recall-only -k 5 "数据库连接超时"            # 只召回不压缩
scx --recall-only -k 5 --field "error_code=conn_id=9f2a"   ✚ 字段定向检索（O1）
scx --rate good 2026-10-22_a1b2c3d4              # 反馈标注（状态机 + 双环）
scx --mem-dir ~/.scx-memory --gc                 # 清理过期
scx --mem-dir ~/.scx-memory --rebuild            # 重建索引（含 qmap 合并、crc 校验）
scx --mem-dir ~/.scx-memory --stats              # 库统计（含桶分布、L1 命中率）
scx --eval baseline.json                         ✚ 可重放评估（O8，见 10 节）
```

新增参数全部可选，默认关闭 → 差分门不受影响。

## 8. 与现有系统的工程一致性

* **模块隔离**：`scx::memory`（I/O 侧）与 `scx::compress`（纯函数）完全分离；compress 不新增任何 I/O。
* **分类器复用**：结构化字段抽取（O1）与实体抽取（3.11）直接复用 `classify.rs` 的 is_err / is_frame / is_lineref / is_diffline，不新增判别逻辑。
* **差分门**：既有压缩输出逐字节不变（N6），作为每个阶段验收门。
* **不变量测试**：新增属性测试 —— 随机语料上断言 seeds==evidence、确定性、fail-open、召回结果不进入正文（mem: 段独立）、坏段自愈（N7）。
* **可替换性**：`embed` / `index` 双 trait，倒排 = 实现一，ANN=feature 开关实现二；存储引擎版本号写入 meta，迁移 = rebuild。

## 9. 分阶段实施路线（v0.2 调整）

每阶段含验收门（门不过不进下阶段）。

| 阶段        | 内容                                              | 成本      | 验收门                   |
| --------- | ----------------------------------------------- | ------- | --------------------- |
| P0 地基     | 统计行移 stderr/--quiet；run.cmd mtime 自举对齐；--lineno（已完成） | 已落地   | 差分门 + golden 门        |
| P1 MVP 记忆 | scx::memory、稀疏倒排、--store/--recall、mem: 段        | 1-2 天   | 差分门 + 单测 + 库往返测试      |
| P2 质量     | PRF、时间衰减、反馈调权、MMR、语义缓存、写后台化；**字段加权（O1）、桶过滤（O6）** | 2-3 天   | 评估集 Recall@5/MRR ≥ 基线 |
| P3 工程化    | 变长编码、量化、mmap、tombstone/rebuild、golden 测试；**qmap 记忆图（O2）、会话缓存（O3）、crc 自愈（O7）** | 2-3 天   | 基准：1 万条库召回 < 5ms      |
| P4 增强（可选） | 实体边、ANN 后端（USearch 形态）、embedding feature 开关；**状态机 + 自适应置信（O4/O5）、评估可重放（O8）** | 2-3 天   | 评估集对拍 A vs B vs 混合    |

## 10. 评估方案（证明 "比模型还好"，而非声称）

* **语料**：真实历史经验库取样 **30-50 组 (query → 人工标注相关 case)**。
* **指标**：Recall@5、MRR、NDCG@10。
* **分层（O8）**：标注集分为三类——字面精确类（错误码/行号/ID 精确复发）、词面近义类（同故障不同词面）、释义类（"上次那个连接池爆掉的问题"）。分别报指标：字面类是统计方法主战场，释义类决定是否值得引入稠密接口。
* **可重放（O8）**：`--eval baseline.json` 以 golden 门同哲学冻结评估输入与期望，改动后重跑可对比，杜绝"换用例偷换指标"。
* **隐式标注扩充（O8）**：除人工标注外，用历史真实 query 与压缩命中的 case 自动生成弱标注对（量大、含噪声），仅用于基线粗筛，最终结论以人工标注集为准。
* 对照：A（自研全套）/ B（本地 bge-small 或 API 跑同 case）/ A+B 混合。
* 预判：A 在字面精确类与词面近义类上系统性胜出（O1 字段加权 + O2 记忆图），释义类 B 胜 —— 这决定稠密接口投入时机。
* 工具：独立 `eval` 子命令输出 NDCG 表，结果入 meta 存档。

## 11. 风险矩阵（v0.2 增行）

| 风险                  | 等级 | 对策                                                   |
| ------------------- | -- | ---------------------------------------------------- |
| 历史过期                | 高  | 时间衰减 + expire\_at + 双阈值，召回带日期，Agent 自行判断             |
| 隐私（日志含路径 / 密钥 / IP） | 高  | 默认不自动存储，--mem-dir 显式开启；库目录 .gitignore；可选 --redact 脱敏 |
| 冷启动无收益              | 中  | 空库自动退化现行为，无噪音                                        |
| 库膨胀扫描退化             | 中  | 分层（3 节规模决策）+ gc + 自压缩（scx 压缩旧库）                      |
| 反馈污染（误标 bad）        | 中  | 权重上下限 + 可回滚 + 标注审计日志 + case 状态机可逆（O4）                |
| 差分门被破坏              | 高  | 任何记忆特性默认关，门禁验收                                       |
| 索引段损坏（断电/中断）       | 中  | 段尾 crc + 魔数 + 坏段丢弃 + rebuild 自愈（O7，N7）                |
| 记忆图老化（query 已过时）    | 中  | qmap recency 字段 + 定期合并 + 过期 query 指纹惰性淘汰（O2）           |

## 12. 开放决策点

1. 全局共享库 vs 每项目隔离库：默认每项目（隐私收紧），`--mem-dir` 指向同一目录即共享。
2. 自动写入开关：默认 `--store` 显式开启（安全优先），后期可用 meta.toml 全局开启。
3. 释义型查询的投入时机：由第 10 节评估数据决定，不预设。
4. 记忆图与语义缓存是否合并为单层：v0.2 设计为并列两环（记忆图管关联、语义缓存管结果），实现期若发现重叠再合并（O2/O3）。
