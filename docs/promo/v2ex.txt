标题：scx 0.11.0 发布：零依赖的查询感知上下文压缩器（crates / GitHub / Homebrew / npm 四平台）

https://github.com/spapient/scx

最近把自己的日志压缩器做到了 0.11.0，四个平台全发了，来聊聊这个东西解决什么问题。

**痛点**：排查问题的时候，一大段日志直接塞给模型，又贵又容易淹掉关键行。通用摘要会改写原文，抽样可能恰好丢掉根因，向量检索不适合逐行保留原始证据。

**scx 的做法**：先确定证据，再分配预算；只删整行，不改写原文。
- 传一个 `--query`（当前问题），命中的证据行 + 最小邻域**无条件保留**，`--ratio` 只能约束可选内容，挤不掉证据
- 输出是原文行子集，可带原始行号，不联网、无随机源、**零第三方 crate**
- 同输入同查询同配置 → 输出逐字节一致（37 个 golden 用例做硬门禁）

**实测数据**（本机 Apple M5 Pro，作者侧自测，非第三方评测）：
- 5 万行日志压缩中位数 11.7–12.0 ms
- 187 万字符 / 5.2 万行：无损 ~50 ms，压掉 61.5%；`--ratio 0.3` 压 75.4%，`0.2` 压 77.9%
- 证据保留：合成 70 条证据行 70/70 = 100% 保留（截断基线 0/70），默认档压减约 82%

**安装**：
```
cargo install scx
brew tap spapient/scx && brew install scx
npx -y @spapient/scx
```

**对 Agent 工作流**：内置 MCP stdio server（零依赖），`scx setup` 一键注册到 Claude / Codex / Cursor（幂等、写前备份、写后自检）。`npx -y @spapient/scx` 也直接兼容千问办公的 MCP 接入方式。

**边界也说清楚**：词面相关优先（零命中就回退原文）；压缩率有证据地板，不是硬承诺；非幂等，累积场景必须对原始文本全量重压缩。

仓库约 4.9 万行 Rust、554 个测试、零第三方依赖。有真实使用场景（排障、长代码问答、agent 上下文治理）的同仁欢迎试用，也欢迎拍砖。
